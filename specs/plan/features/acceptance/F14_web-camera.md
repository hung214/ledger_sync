# 驗收規格：F14 — PWA 即時相機掃描

| 項目 | 內容 |
|---|---|
| 對應需求 | PM 2026-11-17 決策 A（手機記帳體驗升級；零新套件——getUserMedia＋既有 zxing2） |
| 里程碑 / 優先級 | F14 / P1 |
| 所需環境 | PWA（https；iPhone Safari／桌面 Chrome）＋相機權限 |

## 1. 驗收情境（AC）

| # | 情境 | 步驟 | 預期 |
|---|---|---|---|
| F14-S1 | 掃描入口（Web） | PWA／瀏覽器點掃描（FAB/工具列） | 開啟**即時相機頁**（getUserMedia 後鏡頭）＋即時預覽 |
| F14-S2 | 權限拒絕/無 https | 拒絕相機權限（或 http 開啟） | 顯示「相機無法使用」＋**「改用檔案匯入」回退**（不離開流程） |
| F14-S3 | 自動解碼 | 對準電子發票 QR | **自動偵測命中**→加入草稿＋「已掃 N 張」計數；QR 持續在畫面不重複加入 |
| F14-S4 | 多張連掃 | 連續掃多張發票 | 計數累加；「完成掃描」→ 確認清單（ReviewPage）逐張確認入帳 |
| F14-S5 | 附件 | 入帳 | 取景畫面（JPEG 幀）存為附件（內容定址一致） |
| F14-S6 | 桌面瀏覽器 | 桌面 Chrome 開 PWA 點掃描 | 有相機→即時掃描；無相機→回退檔案匯入 |
| F14-S7 | 原生不變 | macOS/Windows/Android App | 掃描行為不變（檔案匯入；相機=SP-2b） |

## 2. 測試現況

- Widget 4（fake controller＋fake decoder）：①相機失敗→回退 ②預覽＋解碼命中＋計數 ③同張去重 ④完成掃描→ReviewPage→返回清空。
- 相機權限/取景/解碼品質：**實機走查**（iPhone Safari PWA＋桌面 Chrome）。
